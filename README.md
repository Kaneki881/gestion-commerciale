# Gestion Commerciale

A Java project that models a small commercial management system with JPA/Hibernate on a MySQL database: categories, products, orders with quantities, and users (clients and suppliers). It includes a generic DAO, a service layer, a product repository with several kinds of queries, and a monthly sales report by category.

> **Status:** the project does not build or start as it is. A few blocking problems are listed in [Known issues](#known-issues), each with its fix.

## Features

- Create categories, products and orders
- Orders made of several lines, each with a product and a quantity
- Product queries: with its category loaded, by category, search by label and price range, and pagination
- Sales report for the previous month: turnover per category
- Generic CRUD through `CrudService` and `GenericDAO`
- A `User` hierarchy (`Client`, `Fournisseur`) mapped with the `JOINED` strategy

## Technologies

- Java (8 or newer)
- Maven, with `war` packaging
- Hibernate Core 5.6.15.Final, configured with `hibernate.cfg.xml`
- JPA API 2.2 (`javax.persistence`)
- MySQL 8 with MySQL Connector/J 8.0.33
- JUnit 4.13.2 and TestNG 7.11.0 (declared in `pom.xml`)

## Prerequisites

- A JDK and Maven
- A MySQL 8 server on `localhost:3306`, with an empty database named `gestion_commerciale`:

  ```sql
  CREATE DATABASE gestion_commerciale;
  ```

- The connection settings in `src/main/resources/hibernate.cfg.xml` use the user `root` with an empty password. Change them to match your server.

## Data model

| Entity | Table | Fields |
|---|---|---|
| `Categorie` | `categories` | `id`, `nom` (required, unique, 100 characters) |
| `Produit` | `produits` | `id`, `libelle` (required, 150 characters), `prix` (required, `DECIMAL(10,2)`), `dateCreation` (set automatically), `categorie` (required) |
| `Commande` | `commandes` | `id`, `dateCommande` (required), `lignes` |
| `CommandeProduit` | `commande_produit` | Composite key (`commande_id`, `produit_id`), `quantite` (required) |
| `User` (entity name `Utilisateur`) | `users` | `id`, `nom` (required, 100 characters). Abstract |
| `Client` | `clients` | `dateInscription` (`date_inscription`) |
| `Fournisseur` | `fournisseurs` | `adresse` |

All identifiers are generated by the database (`IDENTITY`).

### Relationships

```
Categorie 1 ──< Produit 1 ──< CommandeProduit >── 1 Commande

User ◄── Client
     ◄── Fournisseur          (JOINED inheritance)
```

- `Produit` many-to-one `Categorie`, lazy
- `Commande` one-to-many `CommandeProduit`, with `cascade = ALL` and `orphanRemoval`: saving an order saves its lines
- `Produit` one-to-many `CommandeProduit`, inverse side with no cascade
- A product and an order form a many-to-many relationship. It is modeled with the association entity `CommandeProduit`, so the line can hold a quantity. Its key `CommandeProduitPK` is built from both ids with `@EmbeddedId` and `@MapsId`
- `User` uses `InheritanceType.JOINED`: `users` holds the shared columns and each subclass has its own table linked by the id

## Data access and services

### `GenericDAO<T, ID>` and `CrudService<T, ID>`

`GenericDAO` offers `find`, `findAll`, `create`, `update` (with `merge`) and `delete`. Each call opens its own `EntityManager`, and writes run in a transaction that is rolled back on error. `CrudService` wraps it with `getById`, `getAll`, `create`, `update` and `delete`, and rejects `null` arguments.

### `ProduitRepository`

| Method | Description |
|---|---|
| `findWithCategorie(id)` | A product with its category loaded in the same query (`JOIN FETCH`), or `null` |
| `findByCategorie(categorieId)` | Products of a category, using the named query `Produit.findByCategorie` |
| `search(terme, prixMin, prixMax)` | Criteria API search. The label contains the text (ignoring case), and the price is within the bounds. A `null` filter is ignored |
| `findPage(pageNumber, pageSize)` | One page of products ordered by id. **Pages start at 1** |

### `CommerceService`

- `creerProduit(libelle, prix, categorieId)`: the label must not be blank and the price must be given and not negative. Returns the new id.
- `creerCommande(date, quantites)`: `quantites` maps a product id to a quantity. The date and the map are required, the map cannot be empty, each quantity must be positive, and a product cannot appear twice. Returns the new id.

Both throw an `IllegalArgumentException` for invalid input.

### `RapportVentesService`

`chiffreAffairesMoisPrecedent(dateReference)` returns the turnover of the **month before** the reference date, as a map from category name to total, sorted by name. The total of a line is `prix * quantite`. A category with no sale in that month is listed with a total of 0. For example, with the reference date 2026-10-11, orders from 2026-09-01 to 2026-09-30 are counted.

## What the demo does

`App.main` builds the `SessionFactory` through `HibernateUtil`, then:

1. Creates the category "Électronique"
2. Creates the products "Clavier" (49.99) and "Souris" (19.90) in that category
3. Creates an order dated one month ago, with 3 keyboards and 5 mice
4. Prints the order id and the category of the keyboard, read with `findWithCategorie`
5. Prints the sales report for the previous month. The total for "Électronique" should be 249.47 (3 × 49.99 + 5 × 19.90)
6. Closes the `SessionFactory`

## Configuration

Set in `src/main/resources/hibernate.cfg.xml`:

- MySQL database `gestion_commerciale` on `localhost:3306`, user `root`, empty password
- `MySQL8Dialect`
- `hibernate.hbm2ddl.auto=update`: missing tables are created and existing ones are kept, so **data stays between runs**
- `hibernate.show_sql=true` and `hibernate.format_sql=true`: generated SQL is printed in the console
- The mapped classes are listed one by one with `<mapping class="..."/>`
